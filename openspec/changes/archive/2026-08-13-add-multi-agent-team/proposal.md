# Proposal: Add Multi-Agent Team (TL + PD + Engineer)

## Why

当前 workbench 的首次生成是单一 Agent 直通模式：prompt 提交后立即流式生成并自动
执行全部动作——用户在执行前没有审查机会，生成开始后也没有任何角色跟踪"计划是否
真的完成"。对复杂需求，生成方向跑偏或中途漏项都只能靠事后迭代消息纠正，成本高昂。

引入**多智能体团队模式**：三个角色分工协作——

- **TL（团队领导）**：负责统筹。从头到尾推进整个计划——接单后调度 PD 规划、把用户
  批准的计划拆成逐步骤的独立生成轮、驱动 Engineer 执行、跟踪每一步状态，失败时
  暂停交还用户，全部完成后汇总收尾。
- **PD（产品经理）**：负责规划。拆解需求、选择 starter template、产出**产品语言**的
  需求清单（做什么，不含技术实现细节），供用户审查。
- **Engineer（工程师）**：负责执行。即现有 Bolt 单流生成代码，**一行不改**。

两种模式**平级并存**：单智能体模式 = 现状代码原样保留，多智能体团队模式 = 新增
流水线，用户通过输入区的模式开关随时切换。审查闸门**必经**——选了该模式就保证
每次都能审查，AI 不会替用户放行；"跳过"仅用户可按。

**规划贯穿项目全生命周期**：需求往往随迭代越来越复杂，因此规划不是首次生成的
一次性动作——迭代消息先经 **AI 分诊**（小改动直通、大改动进规划），大改动走
PD **增量规划**（注入项目上下文）→ 同样的必审闸门 → TL 逐步骤执行。计划成为
随项目演进的**活文档**。

用户故事：

- **US-T-1**：作为用户，我批准计划后希望 TL 自动逐步推进所有步骤直到全部完成，
  无需我在每一步之间手动发起生成。
- **US-T-2**：作为用户，我提交复杂需求后希望由 PD 先给出需求清单，我确认后再开始
  生成，以免生成方向跑偏浪费时间。
- **US-T-3**：作为用户，我希望随时看到计划执行进度（每步待执行/执行中/完成/失败），
  某步失败时立即暂停并由我决定重试、跳过或终止。
- **US-T-4**：作为用户，我希望随时切回单智能体模式，获得原有的直接生成体验，
  且原代码路径完整保留不受影响。
- **US-T-5**：作为用户，我在迭代中提出较大改动（如"加个登录功能"）时，希望系统
  自动识别并先给出增量计划供我审查，而不是直接闷头生成。
- **US-T-6**：作为用户，我希望小改动（如"改个按钮颜色"）不被重流程拖慢而直通
  生成；若我不同意分诊结论，我可以推翻它（要求规划或要求直通）。

## What Changes

- 新增**模式开关**：输入区发送按钮左侧 pill，**单智能体（默认）/ 多智能体**，
  **对话全周期常驻**（编排进行中禁用切换），选择持久化到 cookie，整体由
  `A2_ENABLE_MULTI_AGENT_MODE` feature flag（默认 false）控制显隐。
- 新增流式规划端点 `POST /api/plan`（PD 角色）：单次调用产出两段结构——starter
  template 选择（`<selection>`）与需求清单（`<plan>`，4-6 条产品语言步骤）；
  规划轮**吞并**现有的 `selectStarterTemplate` 前置调用。
- PD 的 prompt 采用产品经理人设：步骤描述"做什么"，不出现文件名、框架名等技术
  实现细节——技术选型是 Engineer 的职责。
- 新增**审查闸门**：多智能体模式下计划产出后**永远硬闸门**（批准 / 编辑 /
  重新规划 / 跳过），无倒计时、无 AI 自动放行。
- 新增 **TL 编排器**（客户端确定性状态机，无独立 LLM 调用）：批准后接管执行——
  **每个计划步骤一轮独立 Engineer 生成流**，TL 逐条下发步骤指令，轮间自动衔接
  直到全部步骤完成；每轮完成判定 = 流结束 + 动作全部成功落地。
- 新增 **TL 进度面板**：步骤状态列表（待执行/执行中/完成/失败）+ TL 阶段文案
  （"TL：正在调度 PD 规划…"/"TL：正在推进步骤 2/5…"等）。
- **失败即暂停转人工**：任一步骤的生成流错误或动作执行报错立即暂停编排，
  由用户决定重试该步 / 跳过该步 / 终止编排；系统不做自动重试。
- 全部步骤完成后 TL 输出确定性收尾消息（计划完成汇总），随后会话回到常规迭代态。
- 计划以带 `plan` annotation（含 `role: 'pd'`）的 assistant 消息持久化，刷新后
  计划仍可见；编排进度为内存态，刷新不恢复编排。
- 逃生与降级：规划中途可"跳过直接生成"（仅用户可按）；规划调用失败/解析失败自动
  降级为单智能体现有路径；模板拉取失败降级 blank 模板。
- 新增**迭代 AI 分诊**：多智能体模式下每条迭代消息先经轻量非流式分诊（复用
  `/api/llmcall`）——小改动直通原路径；大改动进 PD 增量规划流；分诊结果短暂可见
  且用户可推翻；分诊失败/超时降级直通。
- 新增 **PD 增量规划**：迭代规划轮注入项目上下文（文件树 + 上一版计划及完成态），
  产出"在现有基础上做什么"的增量计划（无模板选择段）。
- 新增**计划活文档语义**：计划 annotation 携带 `gen` 版本号，新批准的增量计划取代
  当前生效计划，历史计划消息保留形成审计链。
- Telemetry 扩展 `phase: 'plan' | 'exec'` 与执行轮 `step` 序号，分阶段统计。

## Capabilities

### New Capabilities

- `multi-agent`: 多智能体团队模式——模式开关、PD 规划端点契约与输出格式（含增量
  规划）、必审硬闸门、计划的审查/编辑/批准流程、迭代 AI 分诊、降级与逃生行为。
- `tl-orchestrator`: TL 编排器——批准后逐步骤自动推进执行（首次生成与迭代增量
  计划均适用）、每步独立生成轮、步骤完成判定、进度可见、失败立即暂停转人工、
  完成收尾、编排降级行为。

### Modified Capabilities

- `workbench`: WB-01（Chat-Based Generation）首次生成在多智能体模式下插入 PD 规划、
  闸门与 TL 多轮逐步骤执行阶段，迭代消息经分诊后可进入同样的团队流；WB-09
  （Response Observability）的状态指示扩展"PD 正在规划"、分诊等待与 TL 执行进度，
  规划轮与执行轮的时间统计分离。

## Impact

- **代码**（全部在 `/workbench` 内）：
  - 新增：`app/routes/api.plan.ts`、PD planner system prompt（首次 + 增量两套）、
    计划解析器、模式开关组件、计划审查卡片组件、TL 编排 hook、TL 步骤指令构造器、
    TL 进度面板组件、分诊 prompt、项目上下文采集器、`a2/config.ts` 新增 flag。
  - 修改：`Chat.client.tsx`（`sendMessage` 首次生成新增多智能体路径、迭代消息分诊
    分流、requestStatus 状态机）、`BaseChat.tsx`（模式开关与 TL 面板挂载）、
    `ResponseStats` 状态类型、telemetry timing annotation 增加 phase/step 区分。
  - 轻量扩展：`/api/llmcall` 支持可选 system prompt 参数（供分诊调用）。
  - **零改动**：单智能体路径（现有 Bolt 流）、`ActionRunner`、message-parser、
    `/api/chat`。
- **API**：新增 `POST /api/plan`（流式 SSE，需认证，走平台默认模型与网关注入密钥，
  支持首次/增量两种上下文）；`/api/llmcall` 增加可选 system 参数。
- **测试**：e2e 需新增 `/api/plan` stub 路由与多轮生成 stub；现有 `llm-stream.ts`
  stub 在单智能体模式下不受影响。
- **指标**：规划轮 TTFT 成为新的第一印象指标；执行轮按 step 拆分统计。

## Scope Boundaries & Non-Goals

- **单智能体代码零改动**：不重构、不抽象现有生成路径；多智能体是纯增量。单智能体
  态下迭代消息直通，分诊也不发生。
- **分诊只做路由，不参与闸门放行**：分诊决定"是否进规划流"；一旦进入规划流，
  硬闸门语义与首次生成完全一致（必审，无 AI 放行）。
- **TL v1 是确定性编排器**：无独立 LLM 调用、无 LLM 验收判断；完成判定依赖
  流结束 + 动作状态信号。角色通过 UI 文案与消息 annotation（`role: 'tl'` /
  `role: 'pd'`）体现，不做 Agent 头像/徽章体系。（分诊是独立的轻量模型调用，
  不属于 TL 编排器。）
- **不做自动重试与自动纠错**：失败立即暂停转人工（用户已选定策略）。
- **不做动作级计划与偏离检测**：计划只含产品语言高层步骤，不逐条对应 boltAction；
  步骤指令只是执行轮的上下文边界。
- **编排会话内生效**：编排状态为内存态，刷新页面不恢复编排（计划消息仍持久化可见）。
- **规划轮不展示 reasoning**：规划界面只呈现结论性步骤。
- **旧 `/src` 三 Agent 流水线不复活**：该目录已废弃；团队模式是 workbench 内的
  全新实现。
